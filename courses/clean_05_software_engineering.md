# Course Specification

## 1. Course Information
- **Course Code:** CPE420
- **Course Name:** Software Engineering Practice

## 2. Learning Outcomes

| CLO | Description | Bloom Level | PLO |
|---|---|---|---|
| CLO1 | Describe common software development lifecycle models and when each applies | Understand | PLO1 |
| CLO2 | Design a software architecture for a multi-service application, documenting trade-offs | Create | PLO3 |
| CLO3 | Function effectively within an assigned role on a small development team | Apply | PLO9 |
| CLO4 | Communicate project status and design decisions clearly in a written report and live demo | Apply | PLO10 |

## 3. Assessment

| Component | Weight (%) | CLO Mapped |
|---|---|---|
| Midterm Exam | 15 | CLO1 |
| Assignment | 15 | CLO1, CLO2 |
| Project | 60 | CLO2, CLO3, CLO4 |
| Attendance | 10 | CLO3 |

**Total: 100**

### Scoring Criteria Checklist
- [x] Rubric published on the LMS before the due date
- [x] Team peer-evaluation form used to adjust individual project scores
- [x] Architecture design deliverable graded against a documented trade-off rubric

## 4. Course Policies
- **Attendance:** Team stand-up sessions are attendance-graded per the weight above; three unexcused absences forfeit that component.
- **Deadlines:** Sprint deliverables follow a fixed schedule; late sprints reduce that sprint's project score by 15%.
- **Academic Integrity:** Team contribution logs (via version control history) are used to verify individual participation claims.
- **Plagiarism and False Citation:** Presenting another team's architecture or a tutorial's design as original work is a violation.
- **AI Tools & Critical Use:** AI tools may be used for scaffolding and documentation drafts; architectural decisions and their justifications must be the team's own and defensible in the live demo Q&A.
